Overview

A non-GUI front end to the live-view and capture protocol.

The camera streams palette-mapped I420 or RGB888 frames over a single plaintext TCP connection. Every command and reply is a small framed message. The CLI selects the geometry and pixel format from the live payload length, and refines the raw grid from PhotoCap. One process per invocation; readable text or JSON output.

Transport

Endpoint
camera:9527 (default)
Framing
token + u32 BE length + payload + CRLF
Auth
none
Client model
one outstanding request; one camera client

Why a whitelist?

Malformed arguments can terminate the device daemon and require a power cycle. The CLI exposes only verified commands and fixed argument sets: init, vFrame, PhotoCap, colorChange+0..7 and four measUnit field pairs. There is no free-form command option.

i
Family support. Length arithmetic covers the Tier 1/2 geometries in UTi-family-protocol-spec.md: I420 or RGB888, optional u16/f32 tails, and display/raw sizes from 120×160 to 640×480. Only the UTi260B+ is hardware-verified; confirm other models before relying on measurements. On the reference firmware a 192×256 f32 plane arrives every 11th vFrame; use --require-plane when a script needs one.

Install & build

Rust 1.95+; Linux desktop libraries are only needed for the GUI binary.

bash
# build both binaries
cargo build --release

# CLI binary
./target/release/utitherm-cli --help

# install on PATH
install -m 0755 target/release/utitherm-cli ~/.local/bin/

The GUI binary is utitherm-viewer. Both binaries share the same protocol, worker and capture decoder. Config is read from ./utitherm.toml or ~/.config/utitherm/config.toml.

✓
No credentials, no fixed IP. Join the camera AP and --ip auto (default) uses the host default gateway. Prefer an explicit --ip 192.168.27.10 in production scripts.

Quick start

Four commands that cover most scripts.

Check the link. utitherm-cli info prints versions, unit and measurement settings.

Grab a frame. utitherm-cli frame --png shot.png --plane shot.f32 --require-plane.

Measure. utitherm-cli --json measure --display 121,161 → JSON with °C.

Capture full resolution. utitherm-cli capture --dir capture → five sections plus optional raw reply.

bash — end-to-end
set -euo pipefail
CAM=192.168.27.10
OUT=./thermal-$(date +%Y%m%d-%H%M%S)
mkdir -p "$OUT"

utitherm-cli --ip "$CAM" --json info > "$OUT/info.json"
utitherm-cli --ip "$CAM" frame \
  --png "$OUT/frame.png" \
  --yuv "$OUT/frame.yuv" \
  --plane "$OUT/frame.f32" \
  --require-plane > "$OUT/frame.json"

utitherm-cli --ip "$CAM" --json measure \
  --temp-file "$OUT/frame.f32" --display 121,161 > "$OUT/sample.json"

utitherm-cli --ip "$CAM" capture --dir "$OUT/capture" --raw "$OUT/capture/raw.bin" \
  > "$OUT/capture.json"

jq -r '.temperature_c' "$OUT/sample.json"

Commands

One process per invocation; each command opens and closes its own session.

READ

info

utitherm-cli info [--json]

Reads the init reply: firmware strings, emissivity, distance, humidity, unit byte, image mode, PiP rectangle and alarm settings.

bash
utitherm-cli info
utitherm-cli --ip 192.168.27.10 --json info | jq '.versions, .unit'

Human output is one key: value per line; JSON is a single object. The raw unit byte is always included, even when its scale is unknown.

READ

frame

utitherm-cli frame [--png P] [--yuv P] [--plane P]

Waits for one new live frame and optionally writes it. The device sends a temperature plane only on every 11th frame; --require-plane keeps requesting until an extended frame arrives.

FlagDefaultEffect
--png <PATH>—Write RGBA8 PNG at the detected display size.
--yuv <PATH>—Write the raw pixel block: I420 or RGB888, size from the detected geometry.
--plane <PATH>—Write the f32 LE temperature plane if present.
--require-planeoffPoll until an extended frame with a plane is received.
--max-frames <N>33Upper bound while waiting for the plane.
bash
# snapshot + plane in one shot
utitherm-cli frame --png shot.png --yuv shot.yuv \
  --plane shot.f32 --require-plane

# JSON metadata on stdout, files on disk
utitherm-cli --json frame --png shot.png --plane shot.f32 \
  --require-plane | jq '{seq, plane}'
!
Without --require-plane, --plane is written only if the first received frame happens to be an extended one. In scripts, always pair them.
READ

frames

utitherm-cli frames --count N --dir DIR

Writes N sampled live frames into a directory. Each sample waits for the newest frame, so sequence numbers may skip while files are written.

FlagDefaultEffect
--count <N>1Number of frames to save.
--dir <DIR>framesOutput directory, created if needed.
--pngautoSave PNG frames.
--yuvautoSave raw pixel frames (`.yuv` for I420, `.rgb` for RGB888).
--planeoffSave _temp.f32 on extended frames.

With no format flag, PNG + raw pixels are written. Supplying any format flag switches to exactly those formats. Plane files appear only on the 11th-frame cadence.

output tree
frames/
├── frame_000123.png          # RGBA8 at detected display size
├── frame_000123.yuv          # I420 raw pixels (`.rgb` for RGB888)
├── frame_000123_temp.f32     # only if an f32 plane arrived
├── frame_000124.png
└── frame_000124.yuv
CAPTURE

capture

utitherm-cli capture --dir DIR

Runs PhotoCap once and writes every section. This is the full-resolution radiometric path; live frames also carry a 192×256 plane, but only on every 11th request. Captures are serialised client-side.

!
No SD-card write. A network capture does not create a file in DCIM/. It takes several seconds (about 10 s when USB is bound), so do not run it in a tight loop. There is no queue: an in-flight capture is never retried, and a 17-byte empty {UTi_Photo} reply disables capture until the camera application is restarted. Do not open a second client or send other commands while a capture is pending; that combination has killed the camera application.
FlagDefaultEffect
--dir <DIR>captureOutput directory.
--name <NAME>captureFilename prefix.
--capture-timeout-ms <MS>30000Wait for the PhotoCap reply.
--raw <PATH>—Also write the full framed reply for replay/offline use.
bash
utitherm-cli capture --dir capture --name scene42 \
  --raw capture/scene42_raw.bin

utitherm-cli --json capture --dir capture \
  | jq '.temperature, .sections.temperature_c'

File naming and byte layouts are documented in Capture files and Raw reply.

IMPORT

import

utitherm-cli import --path DIR

Scans a mounted camera volume read-only, validates every radiometric container, copies it to a host cache and indexes it by SHA-256. Existing hashes are skipped. Thumbnails come from JPEG #1 and are generated on the import worker, never in the render loop.

!
Never write to the camera volume. Mount it read-only where the platform allows. Do not create, rename, delete or repair files, and decline any “scan and fix” prompt. The camera also mounts the same NTFS partition read-write.
FlagDefaultEffect
--path <PATH>scan mountsMount root, DCIM directory, or one .jpg file.
--cache <DIR>usb-cacheHost cache and usb-index.json.
--listoffOnly list already indexed entries; no scan.
--usb-marker <TEXT>[usb] marker, else UNIT UTi260B+Substring expected in AUTORUN.INF; override for another model's label.
bash
# auto-detect a mounted UTi260B+ volume
utitherm-cli --json import --cache usb-cache

# explicit read-only mount, then list what was indexed
utitherm-cli import --path /run/media/$USER/585A980C530F08BD --cache usb-cache
utitherm-cli --json import --cache usb-cache --list

# one file, then sample it offline
utitherm-cli import --path /media/UTi/DCIM/202610240001E.jpg
utitherm-cli measure --usb-file /media/UTi/DCIM/202610240001E.jpg --display 121,161

Auto-discovery requires a mounted volume whose root contains AUTORUN.INF with the configured marker (default UNIT UTi260B+) and a DCIM/ directory. Set [usb] marker in the config or pass --usb-marker for another model. Use --path for non-standard mounts. The GUI has the same importer with a thumbnail gallery.

READ

measure

utitherm-cli measure --display X,Y

Returns one temperature. Source can be the live plane, a saved raw plane, or a saved PhotoCap reply — no camera needed for the latter two.

FlagEffect
--display X,YCoordinate in the detected display frame (240×320 on the reference model).
--plane PX,PYDirect coordinate in the detected raw plane (192×256 on the reference model).
--temp-file PATHRead a raw 196 608-byte f32 LE plane; no network.
--capture-file PATHRead a framed or bare PhotoCap reply; no network.
--usb-file PATHRead one USB radiometric container; no network.

If neither --display nor --plane is given, the centre sample plane (96,128) is used. Display mapping is plane = display × raw/display scale, with no rotation or flip (1.25 on the UTi260B+).

bash
# live plane (waits up to the command timeout for an extended frame)
utitherm-cli --json measure --display 121,161

# fully offline
utitherm-cli --json measure --temp-file scene42_temperature.f32 --display 121,161
utitherm-cli --json measure --capture-file scene42_raw.bin --plane 96,128
utitherm-cli --json measure --usb-file /media/UTi/DCIM/202610240001E.jpg --display 121,161
WRITE

palette

utitherm-cli palette <0..7>

Sends colorChange+<n> (no reply), then inspects following frames and compares their mean-RGB/saturation signature with the measured reference palettes.

Argument / flagDefaultEffect
<INDEX>requiredWhitelisted palette index 0..=7.
--frames <N>6Frames inspected after the request.
--allow-mismatchoffExit 0 even when the signature does not match.
bash
utitherm-cli palette 3
utitherm-cli --json palette 3 --frames 10
!
Palette names/order differ between the spec table and tested firmware. Detection is a heuristic over the decoded frame (OSD included). Treat confirmed:false as “not recognized”, not proof that the request failed.
WRITE

unit

utitherm-cli unit <celsius|kelvin|flag2-clear|flag2-set>

Sends one verified measUnit pair, waits, then re-reads init and checks the relevant bit of the reported byte. Exit is non-zero when the field does not match.

Argument / flagDefaultEffect
celsius—Send measUnit+0+0; clear bit 1 (Celsius), leave bit 2 alone.
kelvin—Send measUnit+0+1; set bit 1 (Kelvin), leave bit 2 alone.
flag2-clear—Send measUnit+1+0; clear the independent secondary flag.
flag2-set—Send measUnit+1+1; set the independent secondary flag.
--settle-ms <MS>800Delay before re-reading init.
--allow-mismatchoffExit 0 even when init reports another byte.
bash
utitherm-cli unit celsius
utitherm-cli --json unit kelvin --settle-ms 1200
!
Bit-field model. The unit byte is not an enumeration: bit 1 is Celsius/Kelvin and bit 2 is an independent flag, so bytes 0, 2, 4 and 6 are all valid. Wire key temperatures stay Celsius regardless. The CLI prints the raw byte and checks only the field it requested.
WRITE

shutter

utitherm-cli shutter

Requests a manual flat-field correction (FFC) with UTi_cmdsys:Shutter. The command has no reply. The device closes the shutter blade, recomputes non-uniformity correction, and every temperature shifts by a small offset afterwards.

!
Measurement epoch. Only compare measurements within one FFC epoch. The GUI detects a simultaneous key-temperature step over a stable scene and clears the live measurement plane for two frames. Run shutter before a measurement series when a clean baseline matters.
bash
utitherm-cli shutter
utitherm-cli --json shutter
STREAM

watch

utitherm-cli watch --json --sample X,Y

Keeps one session open and emits one record per frame. With --json this is JSON Lines, ideal for pipes and log shippers.

FlagDefaultEffect
--frames <N>infiniteStop after N records.
--duration-ms <MS>infiniteStop after a wall-clock duration.
--sample X,Y—Sample this display coordinate using the most recent plane.
bash — JSON Lines

  --sample 121,161 > stream.jsonl

# live CSV of key temperature A
utitherm-cli --json watch | jq -r '[.seq, .key_c[0]] | @csv' > keys.csv

File formats

Every numeric format is headerless; dimensions and byte sizes are the schema.

Live frame formats

PNG

PNG

240 × 320

RGBA8, row-major, alpha 255. Palette and OSD are baked in by the device.

frame --png · frames --png
YUV

Raw YUV 4:2:0

115 200 B

Planar Y, U, V. Y 76 800 B (240×320), U 19 200 B, V 19 200 B (120×160). BT.601 full range.

frame --yuv · frames --yuv
F32

Live temperature plane

196 608 B

f32 LE °C, 49 152 samples, row-major 192 wide × 256 tall, stride 192. Same geometry as the PhotoCap temperature section.

frame --plane · frames --plane · every 11th frame
RAW

Live reply (debug)

115 227 / 311 835 B

Base or extended vFrame, including token, length and CRLF. Not written by default; useful for protocol fixtures.

base = YUV + 12 B keys; extended = base + 196 608 B plane
USB

Radiometric container

~0.6–0.7 MB

Camera DCIM file: one or two JPEGs, interleaved f32 temperatures + aux, metadata. Imported read-only and indexed by SHA-256.

import --path · measure --usb-file

Wire layouts

Base vFrame — 115 227 B total

{UTi_img}9 B token lenu32 BE Y76 800 B U19 200 B V19 200 B keys3 × f32 BE CRLF2 B
token length Y U V key temps CRLF

Byte math: 9 + 4 + 115 200 + 12 + 2 = 115 227. The declared length counts token, itself, payload and CRLF.

Extended vFrame — 311 835 B total, every 11th request

{UTi_img}9 B lenu32 BE YUV 4:2:0115 200 B keys12 B temperature plane196 608 B f32 LE CRLF2 B

Byte math: 115 227 + 196 608 = 311 835. The plane follows the 12-byte key temperatures; it is not before them.

Raw PhotoCap reply

Framing is the same as every other reply; the payload is five length-prefixed sections.

{UTi_Photo}11 B token lenu32 BE total §0len + JPEG §1len + f32 §2len + JPEG §3len + u16 §4len + 8 B CRLF2 B
token total length section 0 section 1 section 2 section 3 section 4

Total length = 11 + 4 + Σ(4 + section_len) + 2. The end tag is inside the declared length.

Section table

Sizes below are the UTi260B+ reference capture; section lengths and the raw/display geometry are authoritative on all family models.

#KindLengthEncoding / geometryFile
0screenshotvariesBaseline JPEG with OSD, 240×320_shot.jpg
1temperature196 608f32 LE °C, 192 wide × 256 tall, stride 192_temperature.f32
2visiblevariesBaseline JPEG, clean, 480×640_vis.jpg
3raw sensor98 304u16 LE, 192×256_y16.u16
4tail8unknown; zeros in reference_tail.bin

Each section is u32 BE length followed by exactly that many bytes. Section 0 and 2 lengths change with JPEG content; 1, 3 and 4 are fixed.

Reading the raw reply

python — parse sections
import struct

blob = open("capture_raw.bin", "rb").read()
assert blob[:11] == b"{UTi_Photo}"
total, = struct.unpack_from(">I", blob, 11)       # total message length
off = 15
sections = []
for _ in range(5):
    n, = struct.unpack_from(">I", blob, off)      # u32 BE section length
    off += 4
    sections.append(blob[off:off + n])
    off += n
assert off + 2 == len(blob) == total
assert blob[off:off + 2] == b"\r\n"

import numpy as np
temp = np.frombuffer(sections[1], dtype="<f4").reshape(256, 192)
y16  = np.frombuffer(sections[3], dtype="<u2").reshape(256, 192)
print(sections[0][:2], sections[2][:2])              # b'\xff\xd8' SOI
✓
Integrity checks in scripts: token equals {UTi_Photo}, declared total equals the file length, every section length stays in bounds, section 1 is exactly 196 608 B, section 3 is exactly 98 304 B, section 4 is 8 B, and the final two bytes are 0D 0A.

USB radiometric files

Second full-resolution source; offline, read-only, no credentials.

!
Read-only by design. The gadget and the camera both mount the same NTFS partition. The client only opens files for reading, copies them to the host cache and never writes, renames, deletes or repairs anything on the camera volume.
JPEG #1240×320 + OSD len2u32 BE JPEG #2480×640 len2u32 BE records49 152 × 8 B metadata4 063 B

Records are interleaved: f32 BE °C then u32 BE aux, 49 152 times. Reading the block as a flat float array yields half garbage.

FieldEncodingNotes
JPEG #1baseline JPEG240×320 with OSD; thumbnail source
len2u32 BEappears before and after JPEG #2; both must match
JPEG #2baseline JPEG480×640, clean image; optional (thermal-only files use len2 = -1)
recordsf32 BE + u32 BE192×256 plane, row-major, interleaved with aux
metadatafixed offsets, ASCII/rawfirmware, model, emissivity, distance, humidity, ambient, unit

Validation and safety

Structure: one or two JPEG SOI/EOI pairs; both length words equal (or the thermal-only -1/0 pair), and size = len(jpeg1) + 4 + max(len2, 0) + 4 + 8×49152 + 4063.

Physics: every temperature must be finite and inside −40…400 °C. A planar/misaligned read produces ±1e30 values and is rejected.

Stability: the worker waits for size and mtime to be unchanged across two samples ~300 ms apart, reads the file in one pass, then copies it.

Identity: SHA-256 of the file is the index key; re-importing the same card does not duplicate entries. Firmware, model, emissivity, distance, humidity, ambient and unit are preserved with the image.

Failure: a rejected file is retried once after ~500 ms, then recorded as unreadable; nothing on the camera is modified.

Live sessions: the GUI pauses USB scanning while a network stream is active. The hardware can run both, but the design rule keeps the live path and import from competing.

Reading an imported plane

python — parse interleaved records
import struct, numpy as np

blob = open("202610240001E.jpg", "rb").read()
# jpeg1_end is the first FFD9; find it in your parser
# records start after: jpeg1 + u32 len2 + jpeg2 + u32 len2
record_size = 8
samples = 192 * 256
temp = np.empty(samples, dtype="<f4")
aux  = np.empty(samples, dtype=">u4")
for i in range(samples):
    off = records_start + i * record_size
    temp[i] = struct.unpack_from(">f", blob, off)[0]
    aux[i]  = struct.unpack_from(">I", blob, off + 4)[0]
plane = temp.reshape(256, 192)

x, y = 121, 161
print(plane[int(y / 1.25), int(x / 1.25)])   # °C
i
Same geometry as PhotoCap. Plane 192×256, stride 192, no rotation or flip, plane = display / 1.25. USB files keep the aux word and settings metadata but drop the u16 raw plane.

Plane mapping

Display and measurement planes share orientation; the scale is exactly 1.25.

Display → plane

formula
plane_x = floor(display_x / 1.25)
plane_y = floor(display_y / 1.25)

index = plane_y * 192 + plane_x

Plane → display

formula
display_x = plane_x * 1.25
display_y = plane_y * 1.25

// sample centre: plane (96,128) → display (120,160)
!
Stride is 192, not 256. Rendering the plane 256 wide tiles it into four bands. The CLI and GUI always use 192. The plane is not rotated or flipped relative to the display.

Behavior & limits

Assumptions that scripts should encode.

Connection

  • One TCP client at a time. Rapid sequential CLI invocations can hit resets while the old socket clears; the worker retries within --timeout-ms.
  • Reconnect backoff: 250 ms → 500 ms → 1 s → 2 s (cap). A fresh init runs after every reconnect.
  • Framing violations always drop the connection; the client never scans for a token.

Streaming

  • One outstanding request; frames are never queued. watch samples the newest frame, so sequence numbers can skip.
  • Target fps is a ceiling. Measured ~18 fps at 20 fps target; the extended-frame cadence is every 11th request.
  • After 5 s without a frame the worker sends HeartBack (no reply, no payload).
  • PhotoCap is serialised client-side. A 17-byte {UTi_Photo} reply with no payload is the sticky busy latch: capture is disabled until the camera application is restarted. The connection and live stream stay up.
  • Palette and OSD are baked into the YUV image; the CLI cannot recolor or hide them.

0Success. For palette/unit, confirmation succeeded or --allow-mismatch was set.
1Runtime failure: connection/timeout, missing plane, unconfirmed palette/unit, PhotoCap parse error.
2Usage error from argument parsing (bad index, unknown flag).

stdout vs stderr: data goes to stdout; reconnect notices, warnings and errors go to stderr. Use --quiet to silence routine retries in scripts.

Troubleshooting

Common failures and the shortest fix.

“camera did not reach streaming”

Wrong IP/interface, camera AP not joined, or another client holds the connection. Try --ip 192.168.27.10, check ip route, or increase --timeout-ms.

Connection reset on every command

The camera allows one client; a previous process or socket may still be closing. Add a short delay between calls, or use watch for a single long session.

No live plane

Planes arrive on every 11th frame. Use --require-plane and raise --max-frames or --timeout-ms. If the firmware never sends one, use capture.

PhotoCap timeout

The device needs several seconds (10 s with USB bound). Raise --capture-timeout-ms. A 17-byte empty reply or a timeout means the capture engine is unavailable; restart the camera application, do not retry in place. No SD-card write is involved.

Unit mismatch

The unit byte is a bit field: bit 1 is Celsius/Kelvin, bit 2 is an independent flag. Byte 2 is valid Kelvin, not a stuck state. The CLI checks only the requested field; use --allow-mismatch for scripts that tolerate a mismatch.

Palette not confirmed

Detection compares frame means with the spec's one-scene references; scene and OSD content shift the numbers, so confirmation is deliberately loose. Inspect detected/distance and use --allow-mismatch if the visual result is correct.
